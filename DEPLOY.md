# Deploy HRMS for free

Free stack: **GitHub** (code) → **Neon** (PostgreSQL database) → **Render** (runs the app: API + website as one service) → **Brevo** (email over HTTPS) → **Gemini** (AI, optional) → **GitHub Actions** (scheduled syncs).

Total cost: ₹0. Time: about 45 minutes the first time.

---

## 1. Database — Neon (you may already have this)

1. https://console.neon.tech → sign in → **New project** → region **AWS Asia Pacific (Singapore)**.
2. **Connect** → copy the connection string. It looks like
   `postgresql://user:password@ep-xxxx-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
3. On your laptop, put it in `backend\.env` as `DATABASE_URL`, then in the `backend` folder:
   ```powershell
   npm.cmd install
   npm.cmd run db:setup
   npm.cmd run set-admin -- admin YourStrongPassword123
   ```
   Your laptop and the online app will share this same database.

## 2. Code — GitHub (private repository)

1. https://github.com/new → name `hrms` → **Private** → Create.
2. Upload the code. Easiest without Git: on the empty repo page click **uploading an existing file**, then drag in the **contents** of your `HRMS` folder **except** these:
   - `backend\.env` (your secrets — never upload)
   - `backend\node_modules` and `frontend\node_modules`
   - `frontend\dist`

   With Git installed instead (recommended — the `.gitignore` already excludes the files above):
   ```powershell
   cd C:\Users\ADMIN\Desktop\HRMS
   git init
   git add .
   git commit -m "HRMS v1"
   git branch -M main
   git remote add origin https://github.com/<your-username>/hrms.git
   git push -u origin main
   ```
3. Check on GitHub that **`backend/.env` is NOT in the repository**.

## 3. App — Render (free web service)

1. https://dashboard.render.com → sign in with GitHub.
2. **New → Blueprint** → select the `hrms` repository → Render reads `render.yaml`.
3. Render asks for the values marked "sync: false". Enter:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the same Neon connection string as on your laptop |
   | `ENCRYPTION_KEY` | **exactly the same** value as in your laptop's `backend\.env` (otherwise saved AI/email keys can't be read) |
   | `APP_URL` | `https://hrms.onrender.com` — use the name Render shows for your service; you can fix it after the first deploy |

   `JWT_SECRET` and `CRON_SECRET` are generated by Render automatically.
4. **Apply / Create**. The first build takes ~5–8 minutes. Watch **Logs** until you see `HRMS API on http://localhost:10000` (Render picks the port).
5. Open `https://<your-service>.onrender.com` → sign in with the admin username and password from step 1.

If the service name differs, go to the service → **Environment** → update `APP_URL` → **Save, rebuild and deploy**.

## 4. Email — Brevo API (works on Render free)

Render's free plan blocks outgoing SMTP (ports 25, 465, 587) since September 2025, so Gmail/Outlook SMTP will time out there. Brevo's API sends over HTTPS instead.
Reference: https://render.com/changelog/free-web-services-will-no-longer-allow-outbound-traffic-to-smtp-ports

1. https://www.brevo.com → free account.
2. **Senders, domains & dedicated IPs → Senders** → add and verify the address you'll send from (they email you a confirmation link): https://app.brevo.com/senders/list
3. **SMTP & API → API keys → Generate a new API key**: https://app.brevo.com/settings/keys/api — copy it (starts with `xkeysib-`).
4. In HRMS: **Integrations → Email → Email service: "Brevo API — recommended for free hosting"** → paste the key → From email = the verified address → From name (e.g. "Deloitte Recruitment") → **Send test email** → **Save**.

Free limit: 300 emails/day. On your laptop you can also use Gmail with an App Password: https://myaccount.google.com/apppasswords

## 5. AI — Gemini free key (optional)

1. https://aistudio.google.com/apikey → **Create API key**.
2. HRMS → **Integrations → AI → Google Gemini → Connect** → paste → **Test before saving** → **Save** → under "Which AI to use" pick Gemini as default → **Save selection**.

Use test data only on free AI tiers; Google may use free-tier data to improve its products.

## 6. Scheduled syncs (Gmail inbox, Google Sheet, APIs) — GitHub Actions

Render's free service sleeps after 15 minutes without visitors, so its internal timer stops. A free GitHub Action wakes it every 15 minutes and runs due syncs.

1. Render → your service → **Environment** → copy the value of `CRON_SECRET`.
2. GitHub → your repo → **Settings → Secrets and variables → Actions → New repository secret**:
   - `HRMS_URL` = `https://<your-service>.onrender.com`
   - `CRON_SECRET` = the value you copied
3. GitHub → **Actions** tab → enable workflows if asked → open **hrms-cron** → **Run workflow** once to test (green tick = working).

## 7. Updating the app later

- **With Git:** change code on your laptop → `git add .` → `git commit -m "update"` → `git push`. Render rebuilds automatically.
- **Without Git:** upload the changed files on GitHub (**Add file → Upload files**, same folder paths). Render rebuilds automatically.
- Database changes are applied automatically on start (`scripts/migrate.mjs`).

## Free-tier limits — know before you demo

| Service | Free limit | What it means |
|---|---|---|
| Render | Sleeps after 15 min idle; ~750 hours/month | First page load after a break takes ~50 seconds. Open it a minute before a demo. |
| Neon | 0.5 GB storage, compute auto-suspends | Enough for a few thousand candidates with resumes. |
| Brevo | 300 emails/day | Fine for pilots. |
| Gemini | Rate limits on the free tier | Bulk AI screening of large batches may pause; screen 25 at a time. |

## Moving to paid later (no code changes)

| Need | Change |
|---|---|
| No sleeping, faster | Render → service → **Settings → Instance type → Starter** (~US$7/month). SMTP (Gmail/Outlook) also works on paid instances. |
| More database space, backups | Neon paid plan, or Azure Database for PostgreSQL — change `DATABASE_URL` |
| Resume files outside the database | Cloudflare R2 / AWS S3 — set `STORAGE_DRIVER=s3` and the `S3_*` values |
| Company email | Integrations → Email → Microsoft 365 (Graph) |
| Enterprise AI | Integrations → AI → Azure OpenAI (India region) |
| Background worker | Add Redis (`REDIS_URL`) and the worker service commented in `render.yaml` |

## Troubleshooting

| Symptom | Fix |
|---|---|
| Build fails on Render | Open **Logs**, copy the first red error, and check `package.json` was uploaded for root, `backend` and `frontend`. |
| "Application failed to respond" | Check `DATABASE_URL` is set and ends with `sslmode=require`. |
| Login works locally but not online | Make sure you used the same Neon database, or run `set-admin` against the Neon URL. |
| Saved AI/email keys show errors online | `ENCRYPTION_KEY` on Render differs from your laptop's. Make them identical, or re-enter the keys online. |
| Test email times out on Render | You chose an SMTP option. Use **Brevo API**. |
